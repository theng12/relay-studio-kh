        Gateway manager token

        Not paired

        Pairing status comes from the native manager.

        A manager token is a credential scoped to the worker IDs Relay controls. Relay uses it to arm dispatch and to set pacing for those workers — it is not the ekw_ worker token an extension uses to claim jobs, and it cannot claim or generate anything itself.

        Mint it in Gateway → Providers → Browser workers, for exactly the worker IDs saved here, or with POST /admin/api/extension-workers/manager passing manager_id and worker_ids. It is shown once; Gateway stores only a hash, and Relay keeps its copy in this Mac’s Keychain.

        Dispatch can also be armed without Relay holding a manager token, from the same Browser workers pane. A worker sitting at 204 is usually dispatch that was never armed, not a failed pairing.

        The token is never shown again after pairing and is never saved in browser storage.

        Gateway's admin pages ask for the browser password set in the Gateway app. They are for watching or changing Gateway itself — never needed to pair Relay or to claim work, and never affect a paired worker.

          What’s New

          Everything that changed in Relay, newest first.

          Force close browsers?

          Open tabs will be lost. Chrome can restore the session the next time it starts. Relay stops only the exact Chrome processes it opened, and never replays work.

          Delete account?

          The Chrome profile folder moves to Relay’s own _trash, so it can be recovered. A browser that is open must be closed first.
